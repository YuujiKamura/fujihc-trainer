# 07 ground truth crosscheck

cyan runner marker bug の地理的事実確認。GPX 原本と course.json の数値、それらが指す実世界の地名、想定 vs 実際を確定する。

## 結論を先に

1. **GPX → course.json 変換は座標を歪めていない** (1968 点 1:1 完全一致、lat/lon/ele すべて誤差ゼロ)
2. **GPX 原本は正規の Mt.富士ヒルクライム公式ルート**: 富士北麓公園付近スタート → 富士山五合目 (吉田口)、24km / 上昇 1242m、ridewithgps 45204897 の中身は本物
3. **dist 1255m 地点 (HUD ele 1132m / slope 2.7%) は 富士スバルライン本線上の 富士河口湖町**。OSM 逆引きで道路名「富士スバルライン」確定
4. **ユーザーの「河口湖町大石付近の住宅地」感覚は誤り**: 大石 (Oishi) 集落は緯度 35.51〜35.52、対する runner 位置は緯度 35.444、両者の直線距離 **約 8.8 km**。runner は大石にいない、いるわけがない
5. **bug は座標ではない別軸**: 座標は完全に正しい、変換も正しい、HUD も座標と整合。「変な場所が映る」と感じる原因は地図 / カメラ / 標高表現の側 (= 07 軸の管轄外、他軸と切り分けが必要)

## 2. 始点・終点の実世界位置

OpenStreetMap Nominatim 逆引き結果:

### Start: (35.45215, 138.75866) ele 1061.3m

- 道路: **富士スバルライン**
- 自治体: 富士河口湖町, 南都留郡, 山梨県
- 郵便番号: 403-0005
- OSM URL: https://www.openstreetmap.org/?mlat=35.45215&mlon=138.75866&zoom=17

公式 Mt.富士ヒルクライムの start (富士北麓公園) は (35.45469, 138.76753) ele 1035m。GPX 始点との直線距離 **852m**。GPX は北麓公園の駐車場・走行待機エリアではなく、**スバルライン本線に既に乗ったあたり** (= 計測区間が始まる胎内洞窟入口交差点付近) を 0m としている可能性が高い。標高も 1061m と公式測定区間の起点 (ele ≈ 1030〜1060m) と整合。

→ **GPX 始点座標は妥当、別ルート参照ではない**。

### End: (35.39399, 138.73109) ele 2303.4m

- 道路: Ochido Trail (御中道) 入口付近の駐車場
- 自治体: 鳴沢村, 南都留郡, 山梨県
- OSM URL: https://www.openstreetmap.org/?mlat=35.39399&mlon=138.73109&zoom=17

これは富士山吉田口五合目 (海抜 2305m 前後) のロータリー / 駐車場エリア。公式コース終点の五合目と整合。

→ **GPX 終点座標も妥当**。

### Runner (dist 1255m 時の位置)

course.json には dist=1255m ぴったりの点はない。idx=60 (dist 1174.82m, ele 1132.4m) と idx=61 (dist 1296.34m, ele 1139.3m) の間。

viewer.js (line 184) のロジック:
```js
while (curIdx < course.length - 1 && course[curIdx + 1].distance_m < curDist) curIdx++;
```
これは `course[curIdx+1].distance_m < curDist` の間しか進まない。curDist=1255m のとき、idx=61 の dist=1296.34 は 1255 より大きいので進まず、**curIdx は 60 で停止**。

リーダー位置 (line 189):
```js
riderEntity.position = Cesium.Cartesian3.fromDegrees(p.lon, p.lat, p.elevation_m);
```
= 点 60 の lat/lon/ele をそのまま使う (補間なし)。

つまり画面上の cyan marker は **(35.44437, 138.75103) ele 1132.4m** にいる。HUD の slope=2.7% も点 60 のもの。HUD の elevation 表示 1132m も点 60 と一致。**HUD と marker 位置は内部整合している**。

逆引き結果:
- 道路: **富士スバルライン**
- 自治体: 富士河口湖町, 南都留郡, 山梨県
- OSM URL: https://www.openstreetmap.org/?mlat=35.44437&mlon=138.75103&zoom=17

→ **runner は富士スバルライン本線にいる、正しい位置**。

## 4. ridewithgps 45204897 と GPX の対応

GPX metadata:
```xml

  <text>Mt.fujihillClimb</text>
</link>

```

ridewithgps 45204897 ページは login wall で raw 座標は取れなかったが、route 名 "Mt.fujihillClimb" + 標高プロファイル (1061m → 2303m, ↑1242m) + 距離 24km は公式 Mt.富士ヒルクライムの計測区間と一致 (公式公表: 計測 24km / 上昇 1255m)。

→ **DL された GPX は別ルートの取り違えではない**。本物の Mt.富士ヒルクライム route。

## 5. なぜ「変な場所が映る」と感じるか (= 別軸が見るべき仮説)

座標・データ・HUD はすべて正しい。にもかかわらず「住宅地が映る」と感じる原因の候補:

1. **viewer.js は `EllipsoidTerrainProvider` を使う** (line 16): Cesium に標高地形が無い、地球が完全な楕円体扱い。富士山も平地として描画される。一方で OSM tile (line 19) は実世界の道や建物を 2D 平面として張り付ける。結果として「平らな地面に道路と建物アイコンが描かれた、富士山の体積がない」絵になる。1132m の山中でも、標高ゼロのフラットな世界に見える可能性。
2. **camera 後方 10m / 上 4m** (line 204) で marker を追う: marker の標高 1132m のあたりにカメラがいるが、地形がフラットなので「斜面を登っている」感覚が消えて、平地の道路の感覚になる。
3. **OSM の zoom 17-19 tile**: スバルラインは森の中だが、OSM では道路と一部の駐車場・施設が描かれる。zoom が浅いと近隣の集落 (河口湖南岸の住宅地、富士吉田市街など) もタイル内に映る。zoom 距離感が狂うと「住宅地寄り」に見える誤認が起きる。
4. **`riderEntity` が discrete-point スナップ** (補間なし): dist 1255m と表示しているのに marker は dist 1174.82m の点にスタックしている。HUD と画面位置が ~80m ずれる (小さい差だが、curIdx が次に飛ぶ瞬間に「テレポート」する違和感は出る)。

→ 07 軸の判定: **bug の主因は「座標が間違っている」ではない**。座標は正確、走者は富士スバルライン本線にいる。「変」と感じる原因は **地形なしフラット地球 + OSM 2D tile + カメラアングル** の合成効果と、**discrete-point スナップによる微小テレポート**。これらは他の軸 (camera / terrain / 補間) で扱うべき。

## 6. ユーザーの期待を直す

ユーザーが想定する「富士スバルライン入口」のイメージは、富士北麓公園を出てすぐの森の登坂路。1255m 地点はそこから 1.25km 進んだ場所で、森の中の蛇行道のはず。住宅地ではない。

実地写真や Google ストリートビューで確認するなら:
- スタート付近: https://www.google.com/maps/@35.45215,138.75866,3a,75y/data=!3m6!1e1
- 1255m 地点: https://www.google.com/maps/@35.44437,138.75103,3a,75y/data=!3m6!1e1
- 五合目: https://www.google.com/maps/@35.39399,138.73109,3a,75y/data=!3m6!1e1

これらを見れば「ここは森の中のスバルライン、住宅地ではない」が確認できる。
