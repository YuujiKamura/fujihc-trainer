# fujihc-trainer フェーズ別設計図 v3 (2026-05-15、 round 3 audit + user 文言指摘 反映)

## このアプリは何か

富士ヒルクライム (= 富士スバルライン公道ロードレース) のコースを、 自宅の室内ローラー (= FTMS 対応 trainer) で再現して走るための練習補助アプリ。 **本人の練習用**が主目的、 **OSS として公開する**のは副次的価値。 室内 trainer の走行を「富士ヒルコースを走った気分にする」simulator、 実走の記録アプリではない。

---

## アクター (= 6 層)

| 階層 | 誰 | どこから触る | 何を期待 | harm への寄与 |
|---|---|---|---|---|
| 1 | yuuji 本人 | 自宅 PC + 室内 trainer | コース起伏で練習 | 自身の評判 / 法的 |
| 2 | OSS clone 勢 | repo を fork | 別コース / 別 trainer 対応 | 派生 fork の責任 |
| 3 | code reader | GitHub repo を読むだけ | 学習 | なし |
| 4a | 自分の trainer を持つ訪問者 (= 「走る」モード) | yuujikamura.github.io/...、 Web Bluetooth で trainer 直接接続 | 富士ヒルコースを室内 trainer で実走 | 訪問者自身 / Strava / 公式 |
| 4b | trainer なしの閲覧者 (= 「観る」モード、 Zwift Climb Portal 風) | 同上、 trainer 不要 | コースを 10 区間に分割、 各区間の平均勾配を見て選択、 rider が fake state で走るのを眺める、 「このコースってどんな登りか」を区間単位で分析 | 軽微 (= ログ保存なし、 Strava upload なし) |
| 4b | 悪意訪問者 | 同上、 XSS / localStorage 改竄 | 攻撃 / 偵察 | 訪問者経由の他 user / yuuji |
| 5 | 法的アクター | 公式 / Strava / OSM / GSI | ToS 遵守、 商標保護、 帰属表示 | 直接の被害者 |

## フェーズ C — 公開 (= GitHub Pages から第三者が触る)

### C-1: intro-overlay (= 説明だけ、 文言確定)

新規 `#intro-overlay` (= z-index 1450)。 ページ読み込み直後に必ず表示、 ボタン押下まで他 UI へ進めない。

**文言 (= user の v2/v3 指摘を反映、 4 文に拡張):**

> このアプリは富士ヒルクライムコースを室内 trainer で再現する練習補助シミュレータです。
> コース起伏は富士ヒルクライム公式が一般公開している GPX を派生変換して使っています。
> 富士ヒルクライム公式が認定 / 後援するアプリではなく、 大会の公式記録にも使えません。
> **元 GPX は屋外計測の GPS データで、 受信状態によって位置・標高に誤差を含みます (= 実際の富士スバルラインの勾配と完全一致しません、 大体合ってる程度の精度です)。 公道は車両以外通行制限があり、 第三者が検証する手段が事実上ありません。 この不確実性を許容してご利用ください。**
>
> データはこの browser のローカルのみで完結します (= サーバ送信なし、 cookie 不使用、 device 跨ぎなし、 browser を消すと履歴も消えます)。
> 2 つのモードがあります:
> - **走る** ── FTMS 対応 trainer (= 室内ローラー) と Chrome / Edge があれば、 Web Bluetooth で直接繋いで負荷連動で走れます。 走行ログを残せます
> - **観る** ── trainer なしでも、 コース全 24km を 10 区間に分け、 各区間の平均勾配を表示、 選んだ区間を rider が一定速度で走る様子を任意視点で眺められます (Zwift Climb Portal と同じ発想、 ただし trainer 不要、 ログ保存なし)
>
> 「自分の trainer で走る」 / 「コースを観る」 / 「閉じる」 の 3 ボタン、 default は何もしない。
> (= 「観る」モードは trainer 不要で立ち上がる、 「走る」モードのみ Web Bluetooth scan + pair が必要。 開発者本人の動作確認用 `?map=1` bypass は URL 引数経由のみ)

「自分の trainer で走る」は consent-overlay (= C-3) に集約。

### C-2: 自動 ride 開始の停止 + introConsented guard (= 2 箇所同時、 B round 3 BLOCK 発見 1 反映)

`bootCheckSetupStatus` の static 分岐 (= viewer-map3d.js:717-723 周辺) **と** module top-level dispatch (= viewer-map3d.js:748 周辺、 `if (MAP_MODE) initMapMode(); else if (TEST_MODE) initTestMode(); ...`) の **両方を guard**:

- intro-overlay 通過 + `setIntroConsent()` (= localStorage に `{hash, accepted_at}` 保存) が前提
- guard 未通過なら `initMapMode` / `initTestMode` / `initBleMode` / `bootCheckSetupStatus` 呼ばない、 intro を表示して待つ
- intro 通過後の default 経路: **`initBleMode` (= Web Bluetooth で trainer 直接接続)** に向かう、 デモ走行ボタンは UI に置かない
- 開発者本人の bypass: `?map=1&consent=dev` / `?test=1&consent=dev` / `?ble=1&consent=dev` のみ skip、 単純な `?map=1` 等は intro 必須
- 単純な `?map=1` 直叩きでも intro を通すが、 通過後の挙動は **MAP_MODE (= 自動 ride デモ)** で、 これは 開発者用 demo のため URL 引数経由でのみ到達、 UI ボタンからは出さない

### C-3: consent-overlay (= ride 開始前の opt-in、 btnRideStart guard、 B round 3 BLOCK 発見 2 反映)

新規 `#consent-overlay` (= z-index 1460)。 既存 `btnRideStart` click handler (= viewer-map3d.js:1331-1336、 現状 `client.isOpen()` のみ check) に consent guard を挿入:

```js
btnRideStart.addEventListener('click', () => {
  if (!client || !client.isOpen()) return;
  // 新規: consent 未取得なら overlay 表示して return
  if (!getRideConsent('asked')) {
    showConsentOverlay();
    return;
  }
  rideState.start();
});
```

**consent 内容**:
- 「走行ログをこの browser に保存しますか」 (= IndexedDB opt-in、 default OFF)
- 「Strava にアップロードする機能を使いますか」 (= 機能解放のみ、 client_id 設定誘導は別、 default OFF)
- 結果は localStorage に hash 付きで保存

**bypass 経路**: `btnConfirmDemo` (= viewer-map3d.js:1353-1359、 デモ走行ボタン) は consent 不要 (= IndexedDB / Strava 両方 OFF declaration 済として扱う)、 v3 で明示。

### C-4: Strava upload 文言 hardcode (= 商標混同対策、 B 発見 3 で layer 修正)

実装 layer は **postride_buttons.js:101-105** (= caller 側)、 ただし caller が override しないよう **strava_upload.js 内でも append 強制**の 2 重 gate:

- `sport_type=VirtualRide` (= 既設定済、 維持)
- `activity_type=VirtualRide` (= legacy 互換のため両方送信、 既存挙動維持)
- GPX `<type>Virtual Ride</type>` (= 既設定済、 維持)
- name: caller 渡し name + ` (fujihc-trainer simulator)` を **strava_upload.js 側で hardcode 接尾**、 caller override 不可
- description: `'This is an indoor trainer simulation of the Mt. Fuji Hill Climb course generated by fujihc-trainer. Not an actual outdoor activity.\n\n' +` を strava_upload.js 側で hardcode prepend

これで caller のミスでも文言が保証される (= 2 重 gate)。

### C-5: 帰属表記 (= round 3 A-L2 で OSM attribution 動的消失 対策追加)

- 既存 attribution control (= 「国土地理院 標高タイル | © OpenStreetMap contributors | MapLibre」) を **CSS `display:none` で消せない gate**:
  - viewer 起動時 1 度、 `getComputedStyle(.maplibregl-ctrl-attrib).display !== 'none'` を assert、 違反したら warning banner 表示
  - 既存 CSP `script-src 'self'` で外部 script 注入は物理 block、 内部 inject (= DevTools 経由) は監視のみで OK (= harm 主体が訪問者本人)
- intro-overlay と footer に「コースは公式 GPX 派生」「公式認定なし」を明記 (= C-1 文言と同期)

### C-6: clearAllLocalData (= 削除 UI、 A-L4 で Strava revoke 実態修正)

設定パネルに「このサイトの全データを削除」ボタン。 確認 dialog 必須 (= 共用 PC で誤動作防止、 B 軸 7 (c) 対策):

- IndexedDB 全削除
- localStorage 全削除 (= Strava token / consent / client_id 含む)
- **Strava 側の token invalidate は client side では不可能** (= `/oauth/deauthorize` は server-side OAuth flow 専用、 CORS で client 直叩き不可)、 既存 strava_oauth.js:185 comment と整合
- 代わりに **Strava 設定ページへの導線リンク** (= index.html:343 既存) を維持、 削除完了 dialog でリンクを再提示
- 削除完了後は intro-overlay からやり直し
- cookie は元々不使用なので削除対象外

### C-7: 同意文の hash 版管理 (= A-L4 で正本明示)

- intro / consent の文言を **build 時に hash 化**、 `web/lib/consent.js` に const `INTRO_CONSENT_HASH` / `RIDE_CONSENT_HASH` として hardcode (= 正本)
- localStorage の保存値は `{hash, accepted_at}`、 比較は `CONST_HASH === stored.hash`
- hash 不一致なら再 consent 要求
- CSP `script-src 'self'` で client side hash 関数の override は物理 block
- 攻撃者が DevTools で localStorage を直接書き換えた場合は harm 範囲が本人 browser 内のみ、 LOAD-BEARING 上限

## 設計原則 (= 価値観列挙、 注記 = 実装難易度 ≠ landing 順序)

1. ガードレールは ToS / 商標 / 第三者権利を起点に発想する
2. 公開時のガードレールは内部構造より先
3. 既にあるものを使え
4. 作ったものは自分で使え
5. サーバに迷惑をかけるな

**注記 (= round 3 A-L1 反映)**: 原則の番号は価値観の重要度であり **実装難易度や landing 順序とは無関係**。 landing 順序は依存グラフで決まる (= DOM 先 → guard → consent → 文言 → 削除 → e2e)。

## インテグレーションテスト要件 (= 各 ε commit に必須、 user 指示 2026-05-15)

ユニットテスト + source-grep だけでは「画面遷移の整合性」を保証できない。 過去訂正「ハンドシェイクが繋がる前でも走り出せる仕様は間違い」(2026-05-14T12:19) を再演しないため、 **起動から画面遷移を端から端まで通す integration test** を整備する。

### 環境

- vitest + happy-dom (or jsdom) で `index.html` を読み込み、 DOM 状態を query
- viewer-map3d.js は maplibre-gl global を持たないと落ちるため、 **module 関数を 1 つずつ抽出 import** (= 既存 lib/check_setup_status.js / lib/consent.js pattern を踏襲) するか、 maplibre-gl を最小 mock で渡す
- Web Bluetooth は `navigator.bluetooth` を mock、 既存 brief 32 の `ble_client.test.js` の mock 構造を流用

### 不変条件 (= integration test で物理 pin、 違反したら CI fail)

1. **intro 通過前は地図 fetch 抑制**: `bootEnv` / `bootMap` を呼ばないことを assert (= ε-2 範囲)
2. **consent 未取得時は ride DB 書込ゼロ**: `addRide` が呼ばれないことを assert (= ε-3 範囲)
3. **Web Bluetooth pair 完了前は「ride 開始」ボタン disabled**: `btnRideStart.disabled === true` を assert、 pair 完了通知 (= `wsHandlers.state` で `state==='paired'`) 後に `false` に遷移することを assert (= ε-3 範囲、 過去訂正 2026-05-14T12:19 反映)
4. **Strava upload 文言の「(simulator)」接尾**: caller が name override しても接尾が残ることを assert (= ε-4 範囲)
5. **clearAllLocalData 後は intro overlay に戻る**: 削除 + reload で再 intro 表示を assert (= ε-5 範囲)
6. **attribution control が `display:none` にされたら warn 発火**: DOM 監視の test (= ε-6 範囲)
7. **地形データ準備完了前は全アクションボタン disabled** (= ε-9 範囲、 user 指摘 2026-05-15、 過去訂正「ハンドシェイクが繋がる前でも走り出せる仕様が間違い」の同型): `terrainReady === false` で `btnTrainerScan` / `btnHrmScan` / `btnSkip` / `btnRideStart` 全部 disabled、 `terrainReady === true` で enabled に遷移、 ステータスバーに「pmtiles 読み込み中 / GSI 標高 読み込み中 / 完了」が表示される

### 画面遷移 integration test (= 端から端まで 1 本)

`web/tests/integration/full_flow.test.js` 新規:

```
# シナリオ: 訪問者が初めて公開サイトを開き、 trainer に繋いで走り、 完走して GPX を取得する

1. ページ読み込み → #intro-overlay が visible、 他 overlay は hidden
2. 「自分の trainer で走る」ボタン押下 → setIntroConsent → #intro-overlay hidden + #consent-overlay visible
3. consent overlay で「ログ保存」「Strava」両 OFF → 「次へ」ボタン → setRideConsent → #consent-overlay hidden + setup-overlay (#ble-section 部分) visible
4. ble scan ボタン押下 → mock bluetooth が trainer device を返す → pair ボタン押下 → wsHandlers.state('paired') → #btnRideStart が enabled (= 不変条件 3)
5. ride 開始 → rideState.start 呼出 → riding 画面に遷移
6. ride 完走 → postride buttons 表示、 GPX download blob 生成可能
```

各 step で DOM 状態 + 不変条件を assert。 全 step 緑なら端から端まで通る保証。

### 各 ε commit ごとの integration test gate

- ε-1: intro overlay の表示 / 「閉じる」で hidden、 setIntroConsent で次画面遷移可能
- ε-2: introConsented=false で initBleMode / initMapMode が呼ばれない、 true で呼ばれる
- ε-3: consent overlay 経由でないと「ride 開始」ボタン押下不可、 pair 完了前は disabled
- ε-4: Strava upload payload の name に「(simulator)」が必ず含まれる
- ε-5: clearAllLocalData → IndexedDB / localStorage 空 + intro 再表示
- ε-6: 全 overlay の z-index 順序 / attribution 監視 / e2e フロー 1 本

各 commit landing 時に `npm test -- web/tests/integration/` も pass を gate に追加。

## zoom 範囲問題の解決方針 (= round 2 で確定済、 v3 で明文化)

DevTools で発覚した「viewer が DB 外 tile を要求 → 404 量産」問題:

- **GSI 再アクセスなし**で解決: viewer の hillshade source に `bounds: [138.65, 35.30, 138.85, 35.50]` (= DB bbox) を設定、 MapLibre に「この範囲外は要求しない」と教える
- 加えて viewer center を bbox 中央 (= 138.75, 35.40) に寄せる、 default view が DB 内に収まる
- これは ε-3 完了後の任意時点で挟める軽い fix (= 工数 30 分)、 公開ガードレールには影響しない
- 外部 request 発生量ゼロ、 既存 DB をフル活用
