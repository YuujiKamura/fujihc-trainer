# 富士ヒル viewer — ユーザー導線フローチャート

## これは何か / なぜ作るか

viewer の全画面と「どの画面から、何を押すと、どこへ動くか」を 1 枚に並べた地図。
個別バグ(観るモードの trap 等)を 1 つずつ叩くのではなく、全体を観てから直すために作る。
flowchart に起こすと「出口の無い画面 (= trap)」「埋もれた導線」が一目で分かる。
出典: web/viewer-maplibre.js / web/index.html / web/lib/consent.js を読んで作成 (2026-05-19)。

---

## 入口 — viewer をどう開くか

```
ページを開く
  → [起動確認中]  (= body.state-checking、DB 充足度と接続環境を確認)
  → 同意の記憶(localStorage)で分岐:
      ・初回(記憶なし)          ──→ [イントロ画面]
      ・前回「走る」を選択済      ──→ [トレーナー接続]   (DB 不足なら先に [DB構築])
      ・前回「観る」を選択済      ──→ [観るモード:区間リスト]      ★欠陥1
      ・?consent=dev / ?test=1 等 ──→ 開発者用、各モードへ直行(イントロを飛ばす)
  → 中断したライドの自動保存が残っていれば ──→ [復元ダイアログ]
```

## 現状の画面遷移

```
[イントロ画面]  intro-overlay (走る / 観る / 閉じる)
   ├ 「閉じる」 → 何も保存せず閉じる(リロードで再表示)
   ├ 「観る」   → 観るモードを記憶 ──→ [観るモード:区間リスト]
   └ 「走る」   → 走るモードを記憶 ──→ [トレーナー接続]

[観るモード:区間リスト]  section-list-panel (右上の常設パネル)
   ├ 区間の行をクリック → その区間を一定速度で走行表示 ──→ [観るモード:走行中]
   └ モード選択へ戻る   → ★欠陥2:この画面に出口が無い(trap)

[観るモード:走行中]
   ├ 別の区間をクリック → その区間へジャンプ
   └ 「区間リストに戻る」→ 引退した旧・全画面モーダル ──→ 「閉じる」──→ [イントロ画面]
                                                          ★欠陥3:出口が奥に埋もれている

[DB構築]  dbinit-overlay
   └ GSI 構築 / OSM 取込 / 地形のみで進む → DB 充足 ──→ [トレーナー接続]

[トレーナー接続]  setup-overlay
   ├ スキャン → 接続 → ハンドシェイク → 準備完了
   ├ 「過去 ride を見る」    → [履歴画面]
   ├ 「コースを観る」        → 観るモードを記憶 ──→ [観るモード:区間リスト]
   └ ライド開始 → 走行ログ同意が未取得なら [同意画面]、取得済なら ──→ [走行中]

[同意画面]  consent-overlay
   ├ 「同意して開始」 → 同意を保存 ──→ [走行中]
   └ 「キャンセル」   → 保存せず ──→ [トレーナー接続]

[走行中]
   ├ 一時停止 / 機器設定スライダー
   └ 「ライド終了」or 完走 ──→ [走行後画面]

[走行後画面]  postride-overlay
   ├ GPX をダウンロード
   ├ 「履歴に保存」 → ★欠陥4:観るモードが記憶に残っていると黙って拒否される
   ├ 「履歴を見る」 → [履歴画面]
   └ (戻る) → [トレーナー接続]

[履歴画面]  history-overlay
   ├ 各ライド行: GPX ダウンロード / 削除
   └ 「閉じる」 → [トレーナー接続]

[復元ダイアログ]  restore
   ├ 「復元」 → 中断したライドの続きへ
   └ 「破棄」 → 通常起動へ

[全データ削除]  (設定内 → clear-confirm → clear-done)
   └ 確認 → 削除 → 同意の記憶も消える ──→ [イントロ画面] からやり直し
```

## flowchart があぶり出す欠陥

4 つの欠陥は別々のバグではなく、1 本の線で繋がっている。

- **★欠陥1 — 再訪ユーザーはモード選択を二度と見ない。**
  前回「観る」を選ぶと、次に開いたときイントロを飛ばして観るモードへ直行する。
  モードを選び直す画面に二度と辿り着かない。

- **★欠陥2 — 観るモードの区間リストパネルに出口が無い (trap の本体)。**
  画面に出るのは右上の区間リストパネルだけ。そこに「モード選択へ戻る」操作が無い。

- **★欠陥3 — 唯一の出口が奥に埋もれている。**
  出口は「区間を 1 つ走り出す → 右上の『区間リストに戻る』→ 引退したはずの旧・全画面モーダル
  → その中の『閉じる』」という 3〜4 ホップ。引退したモーダルが出口として生き残っている =
  設計が濁っている。普通のユーザーは見つけられない。

- **★欠陥4 — 観る記憶が残ると「履歴に保存」が黙って拒否される。**
  走行後画面まで来ても、観るモードが記憶に残っていると保存が拒否される
  (観るモードは記録対象外というガード)。
  ★1〜★3 で観るモードから出られない → 走行記録が永久に保存できない。
  これが「履歴保存できてない」の正体。

線の繋がり: ★1 で観るに固定 → ★2/★3 で抜けられない → ★4 で記録不能。
出口の欠けた 1 つのノード(観るモード)が、履歴機能全体を殺している。

## あるべき形 (design)

flowchart 上で足りない/濁っている辺を直す:

1. **どのモード画面にも「モードを選び直す」出口を常設する。**
   観るモードの区間リストパネルにも、走行モード選択へ戻る出口を常時見える形で置く。
   → [観るモード] ──「モードを選び直す」──→ [イントロ画面] の辺を追加。

2. **出口を 1 経路に統一する。**
   引退した旧・全画面モーダル経由の出口は廃止。出口は常設パネルの 1 ボタンに一本化。

3. **走るモードを選んだ瞬間に観るモードの状態を確実に解除する。**
   イントロで「走る」を選んだら、観るモードの記憶状態 (body.mode-view) を必ず外す。
   外さないと走行後画面が観るモード扱いのままで ★4 が残る。

4. **(検討) 再訪時もモード切替が常に視界にある状態にする。**
   ★1 を完全に消すなら、観るモードへ直行したときも「モードを選び直す」が
   最初から見えていればよい(= 1 で足りる)。イントロ強制再表示までは不要。

この 4 点を満たせば、観るモードは出口のある通過点になり、★1〜★4 が一括で閉じる。
